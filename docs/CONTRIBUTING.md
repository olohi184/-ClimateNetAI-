# Contributing to ClimateNetAI

Thank you for your interest in contributing to ClimateNetAI.

ClimateNetAI is an open research software project focused on climate-aware machine learning for wireless signal prediction. Contributions that improve the scientific quality, reproducibility, usability, transparency, reliability, and responsible development of the project are welcome.

## 1. Ways to Contribute

Contributions may include:

- source-code improvements;
- bug fixes;
- user-interface improvements;
- machine-learning model development;
- model validation and evaluation;
- reproducibility improvements;
- dataset preparation or curation;
- data-quality assessment;
- documentation;
- testing;
- visualization;
- research methodology;
- responsible and trustworthy AI evaluation;
- wireless or atmospheric modelling expertise; and
- other improvements relevant to ClimateNetAI.

Contributors are encouraged to clearly describe the purpose and scope of their proposed contribution.

## 2. Before Contributing

Before making a substantial contribution, contributors are encouraged to review:

- `README.md`;
- `LICENSE`;
- `AUTHORS.md`;
- `CITATION.cff`; and
- `docs/OWNERSHIP_AND_GOVERNANCE.md`.

For major changes to the architecture, modelling methodology, datasets, project scope, or research interpretation, contributors should discuss the proposed change with the project maintainer before implementation.

## 3. Contribution Workflow

A typical contribution may follow this process:

1. Fork the ClimateNetAI repository.
2. Create a dedicated branch for the proposed change.
3. Make and test the changes.
4. Document the purpose and implications of the changes.
5. Commit the changes using a clear commit message.
6. Submit a pull request to the main ClimateNetAI repository.
7. Describe the contribution, testing performed, and any research implications in the pull request.

Contributions may be reviewed for software quality, research validity, reproducibility, compatibility, documentation, and alignment with the scope of ClimateNetAI before acceptance.

## 4. Code Contributions

Code contributions should, where practical:

- follow the existing structure and conventions of the project;
- be readable and appropriately documented;
- avoid unnecessary dependencies;
- maintain compatibility with the supported environment;
- include appropriate error handling;
- avoid silently changing existing research behaviour;
- be tested before submission; and
- explain any changes that affect predictions, model evaluation, or interpretation.

Changes to prediction logic or model-processing behaviour should be documented clearly.

## 5. Machine-Learning Model Contributions

New or modified machine-learning models should include sufficient information to understand how they were developed.

Where applicable, contributors should document:

- model type and implementation;
- input features;
- target variable;
- training procedure;
- preprocessing;
- validation methodology;
- evaluation metrics;
- random seeds or other reproducibility settings;
- software/library versions;
- known limitations; and
- the dataset or dataset version used.

Model-performance claims should be supported by appropriate validation results.

Poor or negative results are valuable research outcomes and should not be hidden merely because a model performs worse than expected.

## 6. Data Contributions

Data contributions require particular care because ClimateNetAI is research software.

Contributors should provide, where applicable:

- the source of the data;
- collection methodology;
- measurement variables and units;
- geographic and temporal scope;
- preprocessing or cleaning procedures;
- known quality issues;
- missing-data handling;
- licensing or permission information; and
- any relevant ethical, privacy, contractual, or institutional restrictions.

Data should not be contributed if the contributor does not have appropriate rights or permission to share it.

Personally identifiable, confidential, restricted, or otherwise sensitive information should not be included in the public repository.

## 7. Research Integrity and Transparency

ClimateNetAI aims to make model behaviour and limitations transparent.

Contributions should therefore not:

- conceal poor model performance;
- selectively remove inconvenient validation results without justification;
- misrepresent model accuracy or generalizability;
- present exploratory findings as established conclusions;
- remove material data-quality warnings without evidence; or
- overstate the operational readiness of experimental models.

Known limitations should be documented openly.

## 8. Reproducibility

Where feasible, research contributions should provide enough information for another researcher to understand or reproduce the analysis.

Contributors are encouraged to document:

- software versions;
- dependencies;
- model parameters;
- data transformations;
- evaluation procedures;
- validation strategies; and
- other settings that materially affect results.

Changes that may affect reproducibility should be highlighted in the pull request.

## 9. Responsible and Trustworthy AI

Contributions that improve the reliability and responsible use of ClimateNetAI are particularly encouraged.

Relevant areas may include:

- robustness evaluation;
- uncertainty assessment;
- explainability and interpretability;
- generalization testing;
- distribution-shift analysis;
- failure-mode analysis;
- model monitoring;
- data-quality assessment;
- fairness and accessibility considerations;
- reproducibility; and
- transparent reporting of limitations.

Prediction outputs should be interpreted together with validation performance, methodological assumptions, and data-quality limitations.

## 10. Documentation Contributions

Documentation contributions are welcome.

Documentation should be clear, technically accurate, and consistent with the research status of ClimateNetAI.

Statements about model performance, scientific findings, datasets, or research conclusions should be supported by the relevant project evidence.

## 11. Attribution and Contributor Recognition

Accepted contributions should receive appropriate attribution based on the nature and significance of the contribution.

Contributor recognition may include:

- acknowledgement in project documentation;
- inclusion in `AUTHORS.md` where appropriate;
- acknowledgement in release notes;
- citation of contributed datasets or software;
- recognition in associated academic publications where the contribution meets applicable authorship criteria; or
- other appropriate forms of attribution.

Where useful, contribution roles may be described using the CRediT Contributor Roles Taxonomy.

Contribution to ClimateNetAI does not automatically confer ownership of the ClimateNetAI project, project identity, or official releases.

Academic authorship is determined separately according to the scholarly contribution made to each publication.

## 12. Licensing of Contributions

Unless explicitly agreed otherwise, contributions accepted into the ClimateNetAI source-code repository are expected to be compatible with the project's MIT License.

By submitting a contribution, contributors should ensure that they have the right to provide the contributed material under terms compatible with the project.

Third-party code, models, datasets, documentation, or other materials must retain their applicable licences, notices, permissions, and attribution requirements.

Contributors should clearly identify third-party material included in a contribution.

## 13. Project Identity

Forks and derivative projects may use the ClimateNetAI source code in accordance with the applicable software licence.

However, a fork or derivative implementation should not represent itself as an official ClimateNetAI release or imply endorsement by the ClimateNetAI project without authorization.

For additional information, see:

`docs/OWNERSHIP_AND_GOVERNANCE.md`

## 14. Review and Acceptance

Submission of a contribution does not guarantee acceptance.

The project maintainer may request revisions or decline contributions based on considerations including:

- scientific validity;
- software quality;
- reproducibility;
- data provenance;
- licensing;
- security;
- maintainability;
- responsible AI considerations; or
- alignment with the scope and direction of ClimateNetAI.

Significant changes to research methodology, model interpretation, datasets, or official releases require appropriate review before integration.

## Research Software Status

ClimateNetAI is an evolving research software platform informed by ongoing doctoral research in Systems Engineering.

The project is under continued research and development and should not be treated as a production telecommunications network-management system. Users and contributors should interpret ClimateNetAI outputs alongside documented validation results, research assumptions, data-quality notices, and study limitations.
